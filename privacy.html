개인정보처리방침 월중계획 자동 등록 · 시행일 2026년 9월 24일 「월중계획 자동 등록」(이하 “이 프로그램”)은 학교 월중계획 문서를 읽어 사용자의 구글 캘린더와 구글 할 일에 일정을 등록하는 데스크톱 프로그램입니다. 이 방침은 이 프로그램이 사용자의 정보를 어떻게 다루는지 설명합니다. 요약 이 프로그램에는 서버가 없습니다. 제작자는 사용자의 어떤 정보도 수집하거나 전송받지 않습니다. 모든 처리는 사용자의 PC 안에서 이루어지며, 바깥으로 나가는 통신은 사용자의 구글 계정에 일정을 넣고 빼는 것과, 그에 앞서 필요한 만큼 읽는 것뿐입니다. 1. 제작자가 수집하는 정보 없습니다. 이 프로그램은 사용자의 PC에서만 동작하며 제작자가 운영하는 서버가 존재하지 않습니다. 사용자의 문서 내용, 일정, 구글 계정 정보, 사용 기록 중 어느 것도 제작자에게 전송되지 않습니다. 분석 도구나 오류 수집 도구도 포함되어 있지 않습니다. 2. 접근하는 구글 사용자 데이터와 그 이유 요청 권한 쓰임 calendar.calendarlist.readonly Google Calendar 캘린더 목록 읽기 ① 등록할 캘린더를 사용자가 고를 수 있도록 캘린더 목록을 읽습니다. 로그인한 계정 주소도 여기서 얻어 화면에 보입니다. calendar.events Google Calendar 일정 ② 사용자가 고른 캘린더에 월중계획 일정을 만들고, 부서별 색(구글이 정한 색 번호)을 붙입니다. ③ 등록하기 전에, 고른 캘린더에서 같은 기간의 기존 일정 날짜와 제목을 읽어 같은 월중계획이 두 번 올라가지 않게 합니다. ④ 사용자가 되돌리기를 눌렀을 때, 이 프로그램이 등록한 일정을 지웁니다. ⑤ 지우기 전에 해당 일정을 다시 읽어 제목이 그대로인지 대조합니다. tasks Google Tasks ① 기한만 있는 업무를 할 일로 만듭니다. ② 할 일 목록을 읽고, 없으면 전용 목록을 하나 만듭니다. ③ 등록하기 전에, 고른 목록에서 같은 기간의 기존 할 일 마감일과 제목을 읽어 중복되지 않게 합니다. ④ 사용자가 되돌리기를 눌렀을 때, 이 프로그램이 등록한 할 일을 지웁니다. ⑤ 지우기 전에 해당 할 일을 다시 읽어 제목이 그대로인지 대조합니다. 캘린더 전체 권한(calendar)은 요청하지 않습니다. 캘린더 자체를 공유 · 생성 · 삭제하지 않습니다. 삭제 권한이 필요한 이유 이 프로그램의 핵심 기능 중 하나는 잘못 등록한 것을 되돌리는 것입니다. 한 번에 수십에서 백 건이 등록되므로, 잘못되었을 때 손으로 하나씩 지우는 것은 현실적이지 않습니다. 되돌리기가 없으면 사용자가 실제 업무용 캘린더에 이 프로그램을 쓰기 어렵습니다. 삭제 대상은 이 프로그램이 등록한 것으로 로컬 기록에 남아 있는 항목으로 한정됩니다. 지우기 전에 구글에서 해당 항목을 다시 읽어 제목을 대조하고, 사용자가 손으로 고친 항목은 건너뜁니다. 프로그램이 만들지 않은 일정은 어떤 경우에도 지우지 않습니다. 기존 일정 · 할 일을 읽는 범위 기존 일정과 할 일은 위의 두 확인(등록 전 겹침 확인 · 지우기 전 제목 대조)에만 읽으며, 등록하는 기간의 날짜와 제목만 읽습니다. 읽은 내용은 바깥으로 보내지 않고 저장하지 않습니다. The only outbound traffic is to the user’s Google account, to create and remove entries and to read what is needed beforehand. calendar.calendarlist.readonly — Lists the user’s calendars so the user can choose where to register. The signed-in account’s address is taken from the same list and shown on screen. calendar.events — Creates the monthly plan events on the chosen calendar, colored by department using Google’s fixed event color numbers. Before registering, reads the date and title of existing events on the chosen calendar for the same period, so that the same plan registered twice does not create duplicates. When the user presses Undo, deletes the events this application created. Before deleting, re-reads each event and checks that its title is unchanged. tasks — Creates tasks for deadline-only items. Reads the user’s task lists and, if its own list does not exist, creates one. Before registering, reads the due date and title of existing tasks in the chosen list for the same period, to avoid duplicates. When the user presses Undo, deletes the tasks this application created. Before deleting, re-reads each task and checks that its title is unchanged. The full calendar scope is not requested. The application never shares, creates, or deletes calendars themselves. Existing events and tasks are read only for the two checks above — the duplicate check before registering and the title comparison before undoing — and only their date and title, for the period being registered. They are not sent anywhere and not stored. The only thing kept on the user’s computer is the record of the entries this application itself created. ← 월중계획 자동 등록
